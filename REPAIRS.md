## Firefox AVIF diagnosis

The pre-fix application produced no 1600×1600 download within 60 seconds. Isolating the same 96×72 synthetic source in the original worker, without the estimator or the application timeout, returned a valid 6,473-byte AVIF in **31.623 seconds**. The 123 scheduled page-heartbeat samples had a 253 ms median, 280 ms p95, and 416 ms maximum gap. Independent Sharp decoding confirmed 1600×1600 and the expected colors. This proves that the old 20-second deadline interrupted a valid, slow encode. Source inspection also confirms that the old AVIF estimator and retry invoked synchronous WASM on the page; the repair moves that work to cancellable workers.

An initial isolation harness used a doubled base path and failed before encoding; its corrected run checked JavaScript MIME and the worker asset hash before measurement. The failed harness is not counted as a product failure.

## Follow-up: full-source bounds and Freeform

User testing identified that the 90% initial baseline also limited the maximum crop after the zoom repair. The baseline now uses the full source bounds: at 1× a fixed-aspect crop reaches the full width or height, and a matching aspect can include the whole image. Regression checks cover all three cases and expansion back to the complete source with a resize handle.

The requested **Freeform** mode sits beside Custom. Entering it preserves the selection, independent edge dragging changes its proportions, and the output follows the selected source dimensions. Selections larger than 7,680 pixels on either side are reduced proportionally; raster dimensions are rounded to whole pixels. Freeform hides the fixed-mode zoom slider while retaining fit controls, and switching back to presets or Custom restores their locked output behavior around the current crop center.

Verification: lint and the TypeScript/production build pass; the complete Chromium suite passes **27/27**, and WebKit passes **4/4** focused Freeform/full-boundary checks. These checks include real JPEG downloads, matching output dimensions and filenames, an 8,000×80 source reduced to 7,680×77, mode switching, unchanged Custom values, and mobile layout. The mobile screenshot was visually inspected. The first new mobile test omitted the existing replacement-image action; correcting that test sequence resolved its file-input timeout without changing application behavior. [Chromium results](docs/audit/repairs/freeform-chromium.txt), [WebKit results](docs/audit/repairs/freeform-webkit.txt), and [mobile preview](docs/audit/repairs/freeform-mobile.png) preserve the follow-up evidence. ## Limits

- Windows Playwright WebKit cannot natively display the generated AVIF, despite producing a valid AVIF file. Its AVIF output is checked with independent Chromium and Sharp decoders; AVIF input/display in that WebKit build remains unsupported.
- Playwright Firefox and WebKit are automated browser builds. Viewport, pointer, and touch emulation do not validate physical Safari/iOS or Android devices. A headed Firefox diagnostic failed to navigate to the local preview and provided no export evidence; it does not establish whether the original delay is headless-specific.
- Screen-reader workflows, a formal accessibility audit, unusual ICC/HDR/HEIC/RAW handling, actual phone capture workflows, 48MP inputs, and maximum 7680×7680 memory use were not proven. Large images/outputs can exceed device resources.
- Original 12MP/24MP and offline observations remain identified as baseline evidence; they are not silently described as new device measurements.
- The audit inspects current source and relevant vendor behavior. It is not an exhaustive vendor-code audit, full history secret scan, exploit exercise, or guarantee that every browser encoder behaves identically.
- There is no installed offline cache. An offline first visit/reload is not guaranteed; AVIF assets must be available. Photos are processed locally, while application assets and Google Fonts can require network requests.
